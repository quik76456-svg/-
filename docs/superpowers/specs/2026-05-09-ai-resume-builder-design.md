# AI 简历优化与导出平台（Web）产品/技术规格（Design Spec）

## 1. 目标与原则

### 1.1 业务目标
- 以“按次+套餐”为主实现快速变现，核心转化点为“下载 Word 前付费”
- 通过身份分层（应届生 / 互联网 1–5 年）提升问答质量与生成效果，形成口碑复购
- 通过加购项与高客单服务扩大利润上限（英文版、岗位定制、Cover Letter、人工精修）

### 1.2 用户目标
- 上传已有简历（PDF/DOC/DOCX），快速获得诊断与可执行改进建议
- 通过 AI 追问补齐信息后生成更强的项目/经历描述
- 一键导出排版稳定的 Word（可选 PDF / 英文版）

### 1.3 产品原则
- 以转化漏斗为第一优先级：登录前置、诊断免费、关键成果付费解锁
- 强约束交付质量：结构化信息 → 模板填充 → 导出稳定，避免“模型直接吐一份 Word 文本”
- 成本可控：模型分层、对话轮次限制、缓存与幂等、导出次数计费
- 合规与安全：简历属于敏感信息，提供删除、最小化保留、下载链接控制

## 2. 范围（MVP / V1 / V2）

### 2.1 MVP（最小可赚钱闭环）
- 手机号注册/登录（短信验证码，阿里云短信）
- 身份选择：应届生 / 互联网 1–5 年
- 简历上传（PDF/DOC/DOCX）与基础解析（提取文本 + 简单分段）
- 诊断报告页（免费）：评分、问题清单、改进方向（不输出可直接复制的完整成稿）
- 付费后：AI 追问补齐信息（多轮问答）+ 生成一份简历版本
- 模板化 Word 导出（至少 1 套模板）
- 支付：支付宝/微信（订单、回调验签、权益发放、幂等）
- 我的简历：历史版本、导出记录、再次优化入口

### 2.2 V1（提升客单与复购）
- 套餐分层：基础/高级/加急（轮次、导出次数、模板数、JD 定制次数）
- 模板切换与多版本生成（同一份信息生成不同风格版本）
- 加购：英文简历、Cover Letter、岗位 JD 定制（粘贴 JD → 关键词对齐与措辞重写）
- 埋点与漏斗：注册→上传→诊断→付费→导出转化率、A/B 测试

### 2.3 V2（利润上限）
- 人工精修与辅导：提交需求 → 客服/简历顾问介入 → 交付与返工
- 模板市场：模板设计师分成、企业版模板
- 企业端：批量简历优化（B 端）

## 3. 用户旅程与页面

### 3.1 主要漏斗
1) 落地页（SEO）→ 2) 手机号登录 → 3) 身份选择 → 4) 上传简历 → 5) 免费诊断 → 6) 购买套餐 → 7) 问答优化 → 8) 预览 → 9) 导出 Word

### 3.1.1 MVP 默认决策（避免歧义）
- 终端优先级：移动端优先（H5），PC 端自适应复用同一套页面
- 支付形态：MVP 先做 Web 收银台（H5），后续再按需要补齐更复杂的支付形态
- 模板数量：MVP 仅 1 套模板保证交付稳定，V1 再扩展多模板与市场
- 简历解析：MVP 以“提取文本 + 简单分段”为主，不追求 1:1 还原版式；解析不准由用户在结构化面板修正

### 3.2 页面列表（MVP）
- Landing：首页/SEO 集合页
- Auth：手机号登录/注册（短信验证码）
- Onboarding：身份选择（应届生 / 1–5 年）
- Upload：上传简历 + 解析进度
- Diagnosis：诊断报告（免费内容 + 付费解锁区块）
- Optimize：问答优化（结构化问答，支持编辑已填字段）
- Preview：简历预览 + 模板选择（MVP 可仅提供一个模板，V1 增加切换）
- Pay：收银台（套餐选择、优惠、支付方式）
- Account：我的简历/订单/导出记录/数据删除
- Admin（内部）：订单、用户、模板、风控、成本、内容审核

### 3.3 关键页面要点

#### Diagnosis（免费但强引导付费）
- 展示：总分（0–100）、结构完整度、关键问题清单（可展开但细节有限）
- 付费墙：展示“可提升点预览”（例如：项目经历需量化、缺少技术深度、缺少成果指标），但不输出完整可复制段落
- 强 CTA：解锁“高级优化 + 可导出 Word”

#### Optimize（问答）
- 聊天式体验 + 结构化字段面板（教育/经历/项目/技能等）
- 每轮问答的目标明确：补齐“背景/规模/职责/难点/方案/指标”
- 提供“我不知道/跳过”与“用示例引导我”分支，降低卡住概率

#### Preview/Export（交付）
- 预览为核心：用户相信排版与内容才愿意付费/复购
- 导出强控制：下载链接短时有效、绑定用户、记录导出次数

## 4. 套餐与定价（建议稿，可调整）

### 4.1 套餐结构（按次 + 权益）
- 基础版：1 次优化会话（固定轮次上限）+ 1 次 Word 导出 + 1 套模板
- 高级版（主推）：更高轮次上限 + 3 次导出 + 多模板 + JD 定制 1 次
- 加急/尊享：更高轮次上限 + 10 次导出 + 多模板 + JD 定制 3 次 + 英文版折扣

### 4.2 加购项（高毛利）
- 英文简历导出
- Cover Letter 生成
- JD 定制次数包（按份/按点数）
- 人工精修（高客单，高毛利，需运营承接）

### 4.3 付费墙策略
- 诊断页可免费，但关键产出（完整成稿、多模板、Word 导出）全部在付费后
- 高级版默认预选（权益对比明显），基础版作为低价入口

## 5. AI 能力设计

### 5.1 输入与标准化
- 上传原简历文件：保留原文件（对象存储）与解析文本（数据库）
- 结构化简历模型（核心字段）
  - 基础信息：姓名（可选）、手机号/邮箱（可选）、城市（可选）、链接（可选）
  - 教育：学校/专业/学历/时间/排名/课程
  - 经历：公司/岗位/时间/职责/成果
  - 项目：项目名/背景/规模/职责/难点/方案/结果指标/技术栈
  - 技能：语言/框架/工程化/数据库/云/工具

### 5.2 诊断（免费）
- 评分维度（可解释）：完整性、可读性、量化程度、岗位匹配度（V1）、技术深度（1–5 年加权更高）
- 产物：问题清单与“下一步要补充的信息”列表（用于引导付费后问答）

### 5.3 追问（付费）
- 根据身份选择问答剧本与权重
  - 应届生：项目/实习叙事与成果、作品集、比赛、课程项目
  - 1–5 年：项目规模、技术难点、决策、指标、协作影响力、owner 贡献
- 轮次控制：按套餐限制对话总轮次与单轮最长输入，超限提示升级
- 生成策略：先补齐结构化字段，再生成最终段落与模板填充文本

### 5.4 生成与润色
- 生成“简历版本”时输出：
  - 结构化字段快照（便于用户编辑与复用）
  - 可渲染的模板字段（用于 Word 导出与网页预览）
- 文案标准：
  - 项目/经历遵循 STAR/XYZ（做了什么/用什么/结果多少）
  - 禁止虚构：模型提示词强约束“不得编造不存在的经历或指标”，对不确定信息要求用户确认

### 5.5 成本与质量策略
- 模型分层：诊断用轻量模型，最终润色/定制用更强模型
- 缓存：解析结果、诊断结果、同参数生成结果可复用
- 幂等：同一版本生成重复请求只返回同一结果

## 6. Word 导出（核心交付）

### 6.1 模板方式
- 使用模板化 docx：预置多套 Word 模板（占位符/内容块），后端将结构化字段填充生成最终 docx
- 模板版本化：模板升级不影响历史版本导出；每次导出记录模板版本

### 6.2 导出规则
- 导出次数扣减与校验（按套餐权益）
- 下载链接短时有效（例如 10 分钟），绑定用户与版本
- 导出水印（可选）：基础版可带轻量水印，高级版无水印（提升升级动力）

## 7. 账号体系（手机号）

### 7.1 登录注册
- 手机号 + 短信验证码
- 防刷：同手机号/同 IP 频率限制、失败次数限制、黑名单

### 7.2 用户资料
- 最小化：除手机号外不强制收集
- 简历默认只对本人可见

## 8. 支付与订单

### 8.1 支付渠道
- 支付宝 + 微信支付（H5/PC 收银台，视产品形态选择）

### 8.2 订单与权益
- 订单状态：created → pending_pay → paid → fulfilled → refunded
- 回调验签：严格校验金额/订单号/商户号一致
- 权益发放幂等：以订单号作为幂等键，重复回调不重复发权益

### 8.3 退款与售后（可选）
- 规则：导出前可退、导出后不可退或部分退（按政策）
- 人工精修为单独商品与交付 SLA

## 9. 数据模型（建议）

### 9.1 核心实体
- users：id、phone、created_at、status
- auth_sms_codes：phone、code_hash、expires_at、sent_at、ip、scene
- resumes：id、user_id、identity_type、source_file_key、parsed_text、parse_status、created_at
- resume_structured_snapshots：resume_id、snapshot_json、created_at
- qa_sessions：id、resume_id、status、started_at、ended_at
- qa_messages：session_id、role、content、tokens、created_at
- resume_versions：id、resume_id、session_id、version_json、template_fields_json、created_at
- exports：id、version_id、format、template_id、file_key、download_token、expires_at、created_at
- products/plans：id、name、limits_json（轮次/导出/模板/JD定制等）
- orders：id、user_id、plan_id、amount、status、provider、provider_trade_no、created_at、paid_at
- entitlements：user_id、plan_id、remaining_generations、remaining_exports、remaining_jd_customizations、expires_at

## 10. 系统架构（建议）

### 10.1 组件
- Web 前端：落地页/登录/上传/诊断/问答/预览/支付/个人中心
- API 服务：鉴权、上传、解析任务、AI 编排、订单与权益、导出
- 异步任务：文件解析、AI 生成、docx 导出
- 存储：对象存储（原文件与导出文件）+ 数据库（结构化数据、订单、日志）

### 10.2 关键技术选型（可替换）
- 数据库：PostgreSQL（交易与结构化数据）
- 对象存储：阿里云 OSS
- 短信：阿里云短信
- 队列/任务：可用轻量队列或云任务服务（按部署形态）
- AI：可接入可配置的模型供应商（便于成本与质量切换）

## 11. 风控与安全

### 11.1 反滥用
- 短信频率限制（按手机号/IP/设备）
- 上传限制：文件大小、类型、每日次数
- 生成限制：按套餐轮次、日限额、异常行为拦截

### 11.2 数据安全与合规
- 加密与脱敏：敏感字段（如验证码）只存 hash；日志不落简历全文
- 数据保留：提供“一键删除简历与生成版本”入口；默认保留策略可配置
- 下载控制：短时 token，防盗链（如存储支持）
- 协议：隐私政策、用户协议、免责声明（AI 不保证录用、禁止虚构经历）
- 内容安全：对生成内容进行敏感信息/违规内容检测；触发时要求用户确认或拒绝导出

## 12. 埋点与增长（赚钱相关）

### 12.1 漏斗指标
- UV → 登录成功率 → 上传成功率 → 诊断到达率 → 付费转化率 → 导出完成率 → 复购率

### 12.2 A/B 测试点
- 诊断页付费墙文案与权益对比
- 高级版默认预选 vs 不预选
- “导出前付费” vs “生成后付费”

### 12.3 SEO 内容策略（V1）
- 词库：应届生简历、项目经历怎么写、STAR 法则、前端/后端/算法岗位简历等
- 模板页：模板可索引（带示例图与权益）

## 13. 验收标准（MVP）
- 能完成：手机号登录 → 身份选择 → 上传 → 免费诊断 → 付费 → 问答优化 → 生成版本 → 导出 Word
- 支付回调可靠：重复回调不重复发权益；支付失败不发权益
- 导出稳定：同一份数据导出 docx 排版一致；下载链接可控且可追溯
- 成本可控：对话轮次与导出次数可配置与校验；异常请求被拦截
